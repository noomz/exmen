# Milestone v1.1: Services & CLI

**Status:** ✅ SHIPPED 2026-03-20
**Phases:** 8-10
**Total Plans:** 4

## Overview

Extends Exmen beyond one-shot script execution into managed long-running CLI
services. Adds a full PTY service engine (SwiftTerm), service lifecycle with
restart policies and keep-alive persistence, a dedicated menu section with
context menu and standalone output window, and CLI commands to script service
control over the existing Unix socket / JSON IPC path.

## Phases

### Phase 8: Long-Running CLI Services

**Goal**: Support long-life arbitrary CLI programs as managed services with start/stop control, output viewing, and full PTY terminal interaction via SwiftTerm
**Depends on**: Phase 7.1
**Plans**: 3 plans

Plans:
- [x] 08-01: SwiftTerm dependency + config models + type contracts
- [x] 08-02: ServiceManager + ManagedService PTY lifecycle + output window
- [x] 08-03: UI views + app lifecycle wiring + end-to-end verification

**Details:**
- Service TOML config with `type = "service"` and `[service]` section
- Menu shows services in separate section with colored status dots
- Right-click context menu: Start, Stop, Restart, View Output
- Full PTY terminal emulation via SwiftTerm in standalone window
- Restart policies: never, on-failure, always (exponential backoff)
- keep_alive option for services that persist after app quit

### Phase 9: Service Context Menu

**Goal**: Service context menu with Start/Stop/Restart/View Output; config reload preserves running services without auto-restart
**Depends on**: Phase 8
**Plans**: 0 plans — satisfied by Phase 8 implementation (08-02 ServiceManager, 08-03 ServiceRowView)

**Details:**
Functionality delivered as part of Phase 8. Config reload matches services by
`action.name` to preserve running services; restart left as an explicit user
action.

### Phase 10: CLI Service Manipulation

**Goal**: Extend the exmen CLI with five commands (list-services, start-service, stop-service, restart-service, service-status) to enable scripting and automation of managed services
**Depends on**: Phase 9
**Plans**: 1 plan

Plans:
- [x] 10-01: Server-side command handlers + CLI client service commands

**Details:**
- Five commands wired end-to-end over Unix socket / JSON IPC
- `ServiceInfo` / `ServiceStatusInfo` Codable structs for typed responses
- `ResponseData` decode disambiguation order documented
- `list-services` supports `--json`; `service-status` shows state, PID, restart policy, keep-alive

## Milestone Summary

**Decimal Phases:**
- None in this milestone

**Key Decisions:**
- SwiftTerm 1.11.2 added as SPM dependency (libghostty C API not embeddable as of 2026)
- ActionConfig.script made optional to support service TOMLs (backward compatible)
- RestartPolicy uses String raw values (`on-failure`) matching TOML spec directly
- LocalProcessTerminalViewDelegate used for PTY exit; dispatched to @MainActor
- ServiceManager.register() matches by action.name to preserve running services on reload
- ServiceOutputWindow uses NSWindowDelegate for windowWillClose
- Services shown below actions in MenuContentView (actions primary, services secondary)
- ServiceRowView: left-click does not toggle; context menu only
- ResponseData decode order: ServiceStatusInfo before ActionStatus; [ServiceInfo] before [ActionInfo] (pid field disambiguates)

**Issues Resolved:**
- Restart getting stuck in restarting state (c2ad718)
- Service process exit not detected — added liveness monitor (cb0c3b7)
- Double-resume crash of CheckedContinuation in ScriptRunner (40c824d)

**Issues Deferred:**
- Phase 10 live IPC verification (5 tests: list/start/stop/restart/status against a live service) — requires running app + service TOML; socket IPC not testable statically. Build-verified and static-verified (7/7 must-haves); live run deferred.
