  <files>Exmen/Services/ActionService.swift, Exmen/ExmenApp.swift</files>
  <action>
**ActionService.swift:**

1. In `loadActions()`, after creating the sorted/filtered actions array and assigning to `self.actions`:
   - Filter service-type actions: `let serviceActions = actions.filter { $0.isService }`
   - Filter regular actions: `let regularActions = actions.filter { !$0.isService }`
   - Set `self.actions = regularActions` (only regular actions in the main list — services are managed by ServiceManager)
   - Call `ServiceManager.shared.register(serviceActions)` to hand service configs to ServiceManager
   - Update the print statement to show both counts: "Loaded \(regularActions.count) actions and \(serviceActions.count) services"

2. The existing ActionService logic (ordering, enable/disable from global config, hook polling) should only apply to regular actions. Services don't use hooks or the script runner.

**ExmenApp.swift:**

1. In `init()`, after existing initialization:
   - Call `ServiceManager.shared.reconnectKeepAliveServices()` to check for previously running keep_alive services

2. Register for app termination notification to handle service cleanup:
   ```swift
   NotificationCenter.default.addObserver(
       forName: NSApplication.willTerminateNotification,
       object: nil,
       queue: .main
   ) { _ in
       ServiceManager.shared.handleAppWillTerminate()
   }
   ```
   This MUST be in init() so it's registered before any quit action.

3. The existing `ProcessInfo.processInfo.disableSuddenTermination()` already ensures the app gets a chance to clean up before terminating — this is important for service shutdown.

**No changes to SocketServer/CommandHandler** — IPC service commands (list-services, start-service, etc.) are out of scope for Phase 8 (can be added later). The IPC `list-actions` command will naturally exclude services since ActionService.actions no longer contains them.
