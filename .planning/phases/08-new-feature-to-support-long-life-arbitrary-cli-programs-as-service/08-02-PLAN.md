Replace the skeleton ManagedService from Plan 01 with full implementation. Import SwiftTerm.

**Known limitation -- stderr vs stdout distinction:**
The CONTEXT.md decision requests "stderr lines visually distinguished (colored red)." This is NOT possible with a real PTY. A PTY (pseudoterminal) merges stdout and stderr at the kernel level into a single stream -- there is no way to distinguish them after the fact. This is an inherent OS-level constraint, not a library limitation. Programs that use ANSI escape codes to color their own error output (e.g., many CLI tools output errors in red via $TERM) will naturally appear colored in SwiftTerm. But Exmen cannot force arbitrary stderr to appear red. Do NOT attempt to work around this (e.g., with separate pipes) as it would break the PTY requirement (programs would see isatty() == false). Accept this as a known limitation of the PTY approach.

**Properties to add:**
- `var terminalView: LocalProcessTerminalView?` (NOT @Published -- it's a reference-type NSView, per research anti-pattern)
- `var outputWindow: ServiceOutputWindow?` (reference to the window controller, set by ServiceManager)
- Private `restartCount: Int = 0`
- Private `restartBackoffTask: Task<Void, Never>?` (for exponential backoff)

**start() method:**
1. Guard `state != .running && state != .starting` (prevent double-start)
2. Set `state = .starting`, `restartCount = 0`
3. Create a new `LocalProcessTerminalView(frame: NSRect(x: 0, y: 0, width: 800, height: 500))`
4. Set `terminalView.processDelegate = self` (for process exit notification)
5. Resolve the executable: if `action.serviceConfig!.command` starts with "/" use it directly, otherwise use "/usr/bin/env" with the command as first arg
6. Call `terminalView.startProcess(executable:args:environment:execName:)` with:
   - executable: resolved path
   - args: resolved args array (prepend command name if using /usr/bin/env)
   - environment: `action.serviceConfig!.resolvedEnvironment` (array of "KEY=VALUE" strings -- check SwiftTerm API: it may want `[String]` not `[String:String]`, convert if needed)
   - execName: action.name
7. If `action.serviceConfig?.resolvedWorkingDir` is set, set the working directory. Note: `LocalProcessTerminalView.startProcess` may have a `currentDirectory` parameter -- check the API. If not, set it via environment or process configuration.
8. Set `state = .running`, `startedAt = Date()`, extract PID from `terminalView.getTerminal()` if available
9. If output window exists and is visible, update its content view to the new terminalView

**stop() method:**
1. Guard `state == .running || state == .starting`
2. Cancel any pending restart backoff task
3. Send SIGTERM to the process group. SwiftTerm's LocalProcessTerminalView should have access to the child PID -- use `kill(pid, SIGTERM)` or the SwiftTerm API equivalent.
4. Set a 5-second timeout: if process hasn't exited, send SIGKILL
5. State transitions handled by processTerminated delegate callback
6. If manual stop (not restart), set a flag to prevent restart logic from triggering

**restart() method:**
1. Set `state = .restarting`
2. Call `stop()` then on completion call `start()`
3. If currently stopped/crashed, just call `start()`

**processTerminated delegate (LocalProcessTerminalViewDelegate):**
1. Dispatch to @MainActor
2. Set `pid = nil`
3. If manually stopped (flag set), set `state = .stopped`, return
4. Based on restart policy:
   - `.never`: set state = exitCode == 0 ? .stopped : .crashed
   - `.onFailure`: if exitCode != 0 AND restartCount < maxRestarts, attempt restart with backoff
   - `.always`: if restartCount < maxRestarts, attempt restart with backoff
   - If restartCount >= maxRestarts: set state = .crashed
5. Exponential backoff for restarts: delay = min(2^restartCount, 30) seconds. Use `Task.sleep` in a stored task.

**attemptRestart() private method:**
1. Increment restartCount
2. Calculate backoff delay
3. Set `state = .restarting`
4. Create a Task that sleeps for the backoff duration then calls `start()`
5. Store the task in `restartBackoffTask` so it can be cancelled on manual stop

**Conform to LocalProcessTerminalViewDelegate** -- implement `sizeChanged`, `setTerminalTitle`, `hostCurrentDirectoryUpdate`, and `processTerminated`. Only `processTerminated` needs real logic; others can be no-ops or minimal.

**Important:** The delegate protocol may be named `LocalProcessTerminalViewDelegate` or `TerminalViewDelegate` -- check SwiftTerm source. The key callback is `processTerminated(_ source: TerminalView, exitCode: Int32?)`.

**ServiceManager.swift:**

Create `@MainActor class ServiceManager: ObservableObject` with `static let shared = ServiceManager()`.

Properties:
- `@Published var services: [ManagedService] = []`

Methods:
- `func register(_ actions: [Action])` -- Takes service-type actions, creates ManagedService for each. Called by ActionService when configs reload. Match by action name to preserve running services on reload (don't restart a running service just because config was re-read). Remove services whose config was deleted. Add new ones.

- `func start(_ service: ManagedService)` -- calls `service.start()`

- `func stop(_ service: ManagedService)` -- calls `service.stop()`

- `func restart(_ service: ManagedService)` -- calls `service.restart()`

- `func showOutput(for service: ManagedService)` -- If `service.outputWindow == nil`, create a `ServiceOutputWindow(for: service)`. Call `showWindow(nil)` and `window?.makeKeyAndOrderFront(nil)`. Activate the app with `NSApp.activate(ignoringOtherApps: true)` so the window comes to front.

- `func handleAppWillTerminate()` -- Iterate all services. For services with `keep_alive = true`: write PID file to `~/.config/exmen/services/{name}.pid` (create directory if needed), do NOT terminate. For services with `keep_alive = false` (default): send SIGTERM, wait briefly, send SIGKILL if needed.

- `func reconnectKeepAliveServices()` -- On app launch, check `~/.config/exmen/services/` for .pid files. For each, verify PID is alive with `kill(pid, 0)`. If alive, find matching service config and set state to .running with the stored PID and startedAt (approximate). Mark that output is unavailable for reconnected services (terminal view is nil). If PID is dead, delete the stale PID file.

- Private `func writePIDFile(name: String, pid: Int32)` and `func readPIDFile(name: String) -> Int32?` and `func deletePIDFile(name: String)` -- PID files stored as plain text at `~/.config/exmen/services/{name}.pid`.

Private init.

**ServiceOutputWindow.swift:**

Create `class ServiceOutputWindow: NSWindowController`:
- Init takes a `ManagedService` reference
- Creates an `NSWindow` with:
  - contentRect: 800x500
  - styleMask: titled, closable, resizable, miniaturizable
  - backing: buffered
  - title: service.action.name + " - Output"
- Sets `window.contentView` to `service.terminalView` (the LocalProcessTerminalView)
- If service.terminalView is nil (reconnected keep_alive service), show a placeholder NSTextField with message "Reconnected to running service - previous output not available. New output will appear after restart."
- Call `window.center()` on first show
- Override `windowWillClose` to nil out the service's outputWindow reference (allow recreation)

The window is deliberately NOT part of the SwiftUI view hierarchy -- it's an independent AppKit window owned by the ManagedService (via ServiceManager). This ensures it survives menu bar popup close/open cycles.
