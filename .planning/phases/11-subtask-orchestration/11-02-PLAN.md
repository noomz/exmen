<objective>
Create the shared subtask data model: `SubtaskConfig` (the single struct decoded by BOTH static `[[subtasks]]` TOML and dynamic `EXMEN:subtask=` inline tables per D-06), `SubtaskState`/`SubtaskStatus` (the observable progress model reused by Phase 12/13 per D-09), and the `subtasks` field on `ActionConfig`.

Per D-02 / D-02a: `SubtaskConfig` stores EXACTLY ONE command representation — an embedded `ScriptConfig`. There is NO stored `cmd: String?` property. The `cmd = "..."` shorthand is a DECODE-TIME ALIAS handled by a custom `init(from:)` that normalizes it into `ScriptConfig(type: .inline, content: ...)`. Both static and dynamic subtasks accept EITHER `cmd = "..."` OR a full `script = { type = ..., ... }` table; supplying both (or neither) is a decode error.

Purpose: Every downstream plan (runner, parser, orchestrator, window) consumes these types. Defining the contracts first prevents a scavenger hunt and makes ORCH-01/ORCH-04 decode testable in isolation.
Output: Three model files compiled into the app target, turning the `SubtaskConfigTests`, `SubtaskStateTests`, and the decode portion of `DynamicSpawnTests` green.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TOML config file → SubtaskConfig decode | User-authored static config; same trust as existing action TOML |
| EXMEN:subtask= inline table → decodeInlineTable | Child-process stdout (user controls the script); untrusted-shaped string crosses into TOMLDecoder |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-11-V5 | Tampering (V5 Input Validation) | `SubtaskConfig.init(from:)` + `decodeInlineTable` | mitigate | Custom decoder rejects ambiguous (both cmd+script) and empty (neither) command specs, and TOMLDecoder enforces TOML grammar (no newline in inline table, no trailing comma); malformed input throws and is caught by the caller (plan 11-05) rather than crashing. A missing required `id` fails decode. |
| T-11-A1 | Spoofing | duplicate/invalid subtask id | accept | id uniqueness/idempotency is enforced by the orchestrator (D-08, plan 11-05), not the model; model stays a pure value type. |
