<objective>
Surface orchestration to the user: build `SubtaskProgressWindow` (a standalone NSWindow reusing the Phase 8 `ServiceOutputWindow` pattern, D-09) hosting a SwiftUI list bound to `SubtaskOrchestrator`'s `@Published` state — colored status dot + name + live elapsed + optional per-subtask bar (D-10/D-12), with an overall percentage header (D-11). Then wire `MenuContentView.executeAction` to branch onto the orchestrator when an action declares subtasks (D-01), open the window, and on completion hand the aggregated summary to `OutputService` as a popup + notification with error severity on any failure (ORCH-05/D-15).

Purpose: This is the only user-visible surface of the phase. Without it, the engine has no UI and ORCH-03/ORCH-05 are unverifiable by a human.
Output: `SubtaskProgressWindow.swift` + the orchestration branch in `MenuContentView`, validated by human checkpoints (visual window + popup/notification) since these are the documented manual-only verifications in 11-VALIDATION.md.
</objective>
